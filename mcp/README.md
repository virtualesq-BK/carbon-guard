# MCP 연결 원칙 — 점진적 신뢰

1. **읽기 전용 도구부터 연결한다.** `fetch`, `filesystem`(읽기), `supabase`(select)를
   먼저 연결하고, 쓰기 권한은 필요성이 검증된 이후에만 추가한다.
2. **모든 쓰기 도구는 `dry_run=true`가 기본값이다.** 에이전트가 명시적으로
   `dry_run=false`를 요청해도, 아래 3번 조건이 없으면 하네스가 거부한다.
3. **실제 쓰기는 `approvals` 테이블에 해당 `checkpoint`의 `status=approved`
   레코드가 있을 때만 실행된다.** 승인 레코드 생성은 사람이 UI 대기열에서
   수행하며, 에이전트나 MCP 서버가 스스로 승인 레코드를 만들 수 없다.

이 파일은 `.mcp.json`에 정의된 서버들이 지켜야 할 계약을 설명한다.
실제 강제(enforcement)는 `hooks/`의 PreToolUse 훅과 각 에이전트 코드의
approvals 조회 로직에서 이루어진다 — 이 문서는 사람이 읽는 설명일 뿐,
코드 없이 이 원칙이 저절로 지켜지지는 않는다.
